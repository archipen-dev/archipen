# Archipen diagrams

An Archipen diagram is one JSON file (`<name>.archipen.json`). Write it by hand following the rules below, check it
with the validator, render it, look at the picture and fix the layout. Users open the file in the editor at
https://archipen.dev/app/ (Open, or drag the file in).

## Workflow

1. **Plan before writing.** List the parts (nodes), the groups they belong to (zones) and the connections (wires).
   Lay the main flow along +x and parallel tiers or replicas along +y, about 4 units apart (x = 0, 4, 8, …). Size
   each zone from its nodes plus 1 unit of padding.
2. **Write the file** following the rules. Leave out every field whose default is fine.
3. **Check and render** with the `archipen` command (Node.js 22 or newer):

   ```sh
   npx -y @archipen/render export diagram.archipen.json -o diagram.png --strict
   ```

   It prints every error and warning with its JSON path and writes nothing if there are problems. Fix all of them.
   In a clone of the Archipen repository, `npm run validate -- --strict <file>` checks without rendering.
4. **Look at the PNG** (if you can view images) and fix what looks wrong: overlapping labels, wires crossing nodes,
   zones that are too tight, an unbalanced layout. Move nodes instead of adding waypoints. Render again until it
   looks like a person drew it. Add `--page <id>` to see a page other than the first.
5. **Without a shell**, check the file against the rules yourself and give the user the JSON as a file to save.

When editing an existing file, keep the ids and everything you weren't asked to change.

## Rules

<!-- rules:start (generated by `npm run schema` from docs/file-format.md) -->
- Top level: {"format": "archipen", "name": ..., "pages": [{"id": "main", "name": ..., "nodes": [...],
  "zones": [...], "edges": [...], "texts": [...]}]}. Items always go inside a page.
  Omit any field whose default is fine; do not output settings unless you change something.
- Use one page unless asked for drill-down. Then make an overview page, one page per detail, and give the
  overview's node or zone "link": {"page": "<detail page id>"}. Wires only connect items on the same page.
- Every item has an "id" that is unique across all items on all pages. Use short readable ids ("api", "db", "e-api-db").
- Units are grid cells. x/y is the corner with the smallest x and y. Nodes default to w=2, d=2, h=1.
  Place nodes about 4 units apart, main flow along +x, parallel tiers along +y.
- Node shapes: "block" (default), "cylinder" for databases/storage, "flat", or "icon" (with
  "iconPlacement": "billboard") for users/devices. Icons: "lucide:<name>" from this list only: the "Built-in icons" list in references/format.md.
  For a named product (Kubernetes, Postgres, Redis, ...) prefer "vendor:<name>" from this list only: the "Vendor icons" list in references/format.md.
- Colours: 6-digit hex only, e.g. #5b7cfa indigo, #2fb5a0 teal, #f2a93b amber, #e5604f coral, #9b6cf0 violet,
  #4aa3df sky, #7dbb52 green, #8a94a6 slate.
- Zones are rectangles {"id", "name", "x", "y", "w", "d"} drawn around the nodes they contain, with about
  1 unit of padding. Nested zones must lie completely inside their parent. Never set zoneId or parentZoneId.
- Edges: {"id", "from": {"nodeId"}, "to": {"nodeId"}}, optional "name" (short label), "style": "dashed" for async.
  An end may use {"zoneId"} instead, to point at a whole zone. Don't set waypoints or ports unless asked.
- Notes: {"id", "kind": "note", "name": title, "description": body, "x", "y"}.
<!-- rules:end -->
